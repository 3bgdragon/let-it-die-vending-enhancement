# 구매·재고 연결 검증 (2026-09-24)

## 검증 수준

빌드 25386710의 실제 EXE 명령을 Unicorn 격리 메모리에서 실행했다.
게임은 실행·수정하지 않았다. `dev/test-native-purchase.py`가 재현 코드다.

실행 범위는 `buyAutomaticshopGoods`의 가격 계산 이후 결제·지급 분기와
`updateAutomaticshopShopping`의 전체 재고 갱신 함수다. DB 조회 결과, 계산된
가격, 잔액 조회/결제 서비스, 아이템 지급 서비스, 문자열 변환·저장 서비스는
모의 구현을 사용한다. 따라서 실제 DB 가격 해석, 아이템 인스턴스 생성,
세이브 직렬화, 재접속, 게임 UI 검증으로 확대 해석하면 안 된다.

## 확인된 연결

- 구매 함수 RVA `0x1141fd0`.
- 결제 서비스 호출 `0x114236f → 0x1345990`.
- 지급 반복 `0x1142480 → 0x13478f0`: pack_count 위치의 수만큼 상품 ID로 호출.
- 킬코인 구매의 재고 갱신 `0x11424da → 0x1358690`.
- stock=1 분기 `0x1358765`: 구매 가능 목록에서 해당 ID 하나를 제거한다.
- 구매 이력 추가 `0x135882e` 이후 및 저장 변경 알림 `0x135891b`.
- 별도 HVN 조건 플래그가 참이면 추가 이력에도 기록한다. 이 이력을 임의로
  삭제하거나 일반 구매 이력과 합치지 않는다.
- 직접 호출자는 RVA `0x1165870`, 구매 호출 지점은 `0x11667ab`.

## 7개 격리 테스트 결과

| 조건 | 결제 서비스 | 지급 호출 | 상품 목록 / 구매 기록 |
|---|---|---:|---|
| 10,000 킬코인·5개 묶음 | 10,000 한 번 | 5 | 목록에서 제거, 기록 추가 |
| 잔액이 가격과 같음 | 한 번 | 5 | 정상 처리 |
| 잔액 9,999 | 호출 없음 | 0 | 변경 없음 |
| 결제 서비스 실패 반환 | 실패 요청 한 번 | 0 | 변경 없음 |
| stock=0 | 한 번 | 5 | 목록 유지, 기록 추가 |
| 목록에 없는 상품 직접 호출 | 한 번 | 5 | 기록 추가 — 상위 차단 확인 필요 |
| HVN 플래그 참 | 한 번 | 5 | 일반 이력 + 별도 이력 추가 |

모든 결과를 assert로 확인했다. 출력의 debits는 성공한 모의 결제만 기록한다.
지급 대상 상품 ID와 변경 알림 횟수도 검사한다.

## 중요한 미완료 사항

**하위 구매 함수 자체에는 구매 가능 목록 포함 여부를 강제하는 차단이 없다.**
stock=1은 성공 후 목록 제거를 수행하지만, 직접 다시 호출하는 것을 막지 않는다.
이것만으로 실게임에서 재구매 문제가 발생한다고 단정할 수는 없으나,
메뉴의 상품 목록 갱신·연속 입력·오래 열린 확인창을 검증해야 한다.

또한 같은 세션/재접속 품절 유지, 일일 목록 재생성 후 재입고는 실제 저장 경로와
연결한 통합 테스트가 필요하다. 현재 결과는 결제·지급·재고 갱신 **호출 연결**의
확인이며, 설치 가능한 모드의 완성 검증이 아니다.
