# 탄약 충전 개발 기록

## 확정 가격 정책

사용자 지정: **해당 무기의 구입 가격 1/5**.

- 선택한 무기 한 자루의 장전탄과 예비탄을 완충하는 고정 비용이다.
- 같은 계열이라도 해당 무기 종류·강화 단계의 구입가를 사용한다.
- 판매가, 계열 기본 무기의 가격, 남은 탄약 비율로 대체하지 않는다.
- 소수점은 1킬코인 단위 올림. 예: 50,000 → 10,000, 50,001 → 10,001.
- 이미 완충된 무기는 선택·결제에서 제외한다.
- 구입가를 확인하지 못하거나 보유 킬코인이 부족하면 충전을 거부한다.
- 탄약만 충전하며 내구도·강화·장비 ID는 변경하지 않는다.

`src/ammo-price.js`와 `tests/ammo-price.test.js`는 이 정책의 기준 구현과 내부 테스트다.
실제 게임에서는 `patches/vending-build25386710.json`의 스크립트 삽입 계획을 적용한다.
게임이 Node 모듈을 호출하는 방식이 아니라 설치 도구가 UPK를 수정하는 방식이다.

## 연결 조사 결과와 남은 검증

- 일반 상점의 `BrgUIMenu_ShopBase` 데스백 목록을 재사용한다.
  `SellItem`에 자판기 탄약 모드 전용 선행 처리를 삽입하고 모든 경로에서 원래 판매 코드 전에 반환한다.
  실제 데스백은 유지하고 임시 표시 목록만 탄약형 무기로 필터링한다.
- `CreateItemMiniPanelInfo_Part`에 구입가 표시 경로가 있다.
  구입가 표시로 호출해 반환된 `mDrawInfo.mPrice`를 1/5로 환산한다.
  판매가 조회 대신 이 가격 필드를 확인/결제에 직접 사용한다.
  구입가와 실제 무기 강화 단계의 일치는 실게임 가격 대조가 필요하다.
- 장착 무기는 장착 배열과 데스백 값을 함께 다룬다. `UpdateUserData`가
  런타임 값을 저장 자료에 복사하므로 저장 자료만 수정하면 값이 되돌아갈 수 있다.
- 충전과 차감 후 `StartUpdateResearch`로 기존 저장/오류 재시도 경로에 연결했다.
  저장 재시도 상태에서는 결제 코드를 다시 호출하지 않는다. 일반 판매 이력은 추가하지 않는다.
- 확인 직전에 무기 ID로 실제 데스백 위치·탄약·내구도·잔액을 재검사한다.
  `SetMoney`가 실패하면 탄약은 변경하지 않는다. 장착 배열 8칸 중 같은 ID만 함께 충전한다.
- 모의 엔진에서 생성 바이트코드의 가격·목록·취소·차감·재시도·동기화를 실행했다.
  **실제 엔진 구입가 계산, 오프라인 DB 저장, 저장 후 재접속은 아직 미검증**이다.
- 정렬 시 판매 플래그와 필터 목록이 섞이지 않도록 탄약 메뉴의 정렬 키는 초기판에서 막는다.

게임 설치 원본과 세이브는 개발 중 변경하지 않았다. 별도 복사본에서 통합 적용과 전체 복원을 검증했다.
