# 자판기 데칼 교체·탈착 — 시험 패치 구현

빌드 25386710, 도구 0.3.0-dev. 통합 적용 메뉴에서 EXE·DB·UPK를 실제 변경합니다.
**실게임 검증 전**이며 분석 후보만 찾은 단계와는 구분합니다.

## 연결한 흐름

1. SetupTopMenu: 기존 항목 뒤, 자동 종료 항목 앞에 ‘데칼 교체 / 탈착’ 추가.
2. GetMenuDefinition: 구매 전용/블러드늄 숨김 조합에 맞춰 새 항목·종료 매핑.
3. 자판기 TickASync: 선택 시 상태 18. 기존 상위 메뉴를 닫고 입력 정지.
4. UIManager 소유 SkillExchange 생성·초기화, 전용 표식 mTopMenu=250 지정.
   이 호출만 가챠·NPC 연출을 생략하고 기존 데칼 관리 상태 8로 시작.
5. 기존 StartPut → GetResult → NetSendHistory가 현재 파이터/보유 데칼과 변경 이력 처리.
   저장 대기/오류/재시도 로직은 기존 함수 본문 그대로 사용.
6. 변경 없이 취소하거나 저장 성공 후 상태 3에 도달하면 정리. UIManager가 종료 객체를
   해제한 뒤 자판기 상태 7로 복귀. 일반 종료의 입력 해제·Momoko 이벤트는 실행하지 않음.

SkillPut의 일반/프리미엄 탈착 규칙, ApplyStickerToPawn, OnPutSkill,
NetSendHistory, RequestMushroomshop 함수는 수정하지 않습니다.
일반 버섯상점은 전용 표식이 없어 기존 진입·종료 경로를 사용합니다.

데칼 전용 화면에서는 SkillPut만 그려 초기화하지 않은 가챠 폰트·배너를 사용하지 않습니다.
전역 네트워크 오류 대화상자는 기존 UIManager가 처리합니다.
자판기로 돌아갈 때에는 게임 입력 잠금과 배경을 유지하고 자판기 자체를 종료할 때 원래 방식으로 해제합니다.

## 파일 패치

대상 함수 8개의 원본 SHA-256을 검사합니다. 패치에는 게임 패키지 전체가 아닌
추가 바이트코드·분기 재배치 정보만 포함합니다.

- 기존 함수 본문에 삽입하고 절대 분기 주소를 런타임 위치 기준으로 재배치.
- 객체 참조의 디스크 4바이트/런타임 8바이트 차이 반영.
- 확장 함수를 마지막 압축 구간에 배치하고 export 크기/오프셋 갱신.
- 변경 구간만 재압축하고 재해제 검증.
- 실행 파일의 두 BrgGame.upk SHA-1 항목 갱신.
- UPK도 자동 백업/복원. 이후 다른 변경이 있으면 복원 거부.

2026-09-24:

- 실제 설치 패키지의 대상 함수 해시 일치 및 복사본 패치 성공.
- UELib로 수정 함수 8개 재역분석: 모든 런타임 길이와 분기 목적지 일치.
- 연결 바이트코드 52개 모의 시험: 메뉴 조합/인덱스, 중복 진입 방지,
  저장 대기/오류 중 유지, 완료 후 복귀, 일반 버섯상점 경로 보존.
- 게임 파일 복사본에서 적용·바이트 단위 복원, 기존 상품 보존, 이중 적용 거부,
  이후 변경 시 복원 거부, 설치 원본 해시 보존.

저장 후 재접속 유지와 오류 재시도는 아직 검증하지 않았습니다.
